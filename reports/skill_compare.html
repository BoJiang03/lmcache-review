lmreview 对比 /pr-review 和 /code-review

20 个历史 PR 样本：学过的 10 个，没学过的 10 个。对比对象是 /pr-review（LMCache 仓库自带）和 /code-review（Claude Code 自带），都用 Opus 5.5 medium，同一个盲评判分器。2026-11-26。

结论

学过的 PR：全面超过命中 83% 对 51%；每样本成本 $0.88 对 $0.87，基本持平；时间 90 s 对 118 s。
没学过的 PR：追平命中 68% 对 65%；成本 $1.04 对 $1.18；时间 114 s 对 159 s。
重要问题漏得少major 命中 17/20，/pr-review 是 13/20；两边 blocker 都是 4/5。
对 /code-review：命中远超，成本略高命中 78% 对 33%；每样本成本 $0.96–1.17 对 $0.59–0.78。

下面前几节都是和 /pr-review 的对比，其中 lmreview 的 rule check 用 low。和 /code-review 的对比单独一节，用的是正式配置，rule check 用 medium。

lmreview 漏掉的是什么

漏掉 18 个要点，另有 11 条提问（提问不是 AI 该回答的）。

  • blocker 1：rebase 到 dev 之后接口签名不匹配，导致 mypy 报错。这需要知道当时的 base 分支状态，离线回放拿不到。
  • major 3：reserve_write 和 reserve_read 之间 key 可能被驱逐的竞态；lookup 状态代码要更模块化；异步 L2 读锁导致的 flaky 测试。
  • minor 7：大多是需要项目背景的取舍，比如拆成单独的 PR、把函数挪到单独文件、两个监控指标重叠、删掉的 docstring 里有一句该保留、单测里不要 import vllm。
  • nit 7：口味型意见，比如改名（num_groups → num_object_groups）、辅助函数放到类末尾、import 放顶部、撤回不必要的改名。

这些漏掉的评论会进入学习流程，变成规则。学过的组命中更高，就是这么来的。

/pr-review 只有 error / warning / info 三级，没有 blocker 这一级，所以只列 error 一行，按 major 来比。"判分模型认为成立"是 AI 自己的判断，不是 gold，还需要人逐条确认。

lmreview 报的深层问题更多，有四个原因：

  • 侧重正确性：prompt 要求报所有真实问题，正确性排第一，发现 bug 还要给出回归测试。blocker/major 中带"崩溃、泄漏、竞态、数据错乱"这类字眼的，lmreview 有 45 条，/pr-review 有 28 条。
  • 跟进之前的 review：之前评论过、这一版还没修好的问题会再报一次。lmreview 有 9 条属于这一类，/pr-review 0 条。
  • 可以查 vLLM 源码：用来核对 PR 对 vLLM 行为的假设。提到 vLLM 的条目，lmreview 22 条，/pr-review 11 条。
  • 级别划分：blocker/major 只留给行为错误。规范类问题两边都是 12 条。

  • 命中：lmreview 远高于 /code-review，78% 对 33%。只有 lmreview 抓到的要点有 35 个，只有 /code-review 抓到的 0 个。/code-review 只在 blocker 上打平，major 以下的维护者意见基本抓不到。
  • 成本：/code-review 便宜约 35–40%。它查得浅，小 PR 上只花 $0.3–0.5，不到 1 分钟。时间两边差不多。
  • 人类没提的问题：/code-review 的 important 里，判分模型认为成立的占 70%（40/57），lmreview 的 major 是 96%（55/57）。这一项是 AI 的判断，不是 gold。
  • 还差什么：成本这一项 lmreview 还没追平 /code-review。

/code-review 的级别映射为：important → major，pre_existing → minor，nit → nit。它的输出格式不固定，所以统一用一次小调用抽成 JSON，这部分成本（每个 PR 约 $0.08）已经算在它的成本里。

配置和附带结论

  • lmreview：p29d23a9f+v0032@medium-rc。主审 medium，带 /pr-review 的检查清单、设计文档检查、批量读取，只输出 JSON。rule check 用 low，和主审并行，不带工具。之后用一次小的 Sonnet 调用去掉 rule check 里与主审重复的条目。
  • /pr-review：今天的 .claude/skills/pr-review/SKILL.md 加 docs/coding_standards.md，离线运行，然后用一次调用把 Markdown 报告抽成 JSON。
  • high 换成 medium（6 个样本）：lmreview 命中 70% → 70%，成本降 25%；/pr-review 命中 59% → 49%。
  • 去重：20 个 run 中，rule check 的 72 条 findings 去掉了 25 条，人类评论命中损失 0，每个 PR 约 $0.011。

局限：每组只有 10 个样本；没学过的组都是较新的 PR（#5000 以后），学过的组是 #3200–#4700，所以两组之间的差异还混有时间因素；#3869 一个样本就占学过组 17 个要点；判分是 AI 盲评。数据在 data/skill_compare/，脚本是 scripts/skill_compare.py。
